title: Setup Gamified Offer
---

<Info>
A **Gamified Offer** rewards customers for achieving **multiple predefined milestones (levels)** within a configured subscription cycle. As customers reach each configured milestone, they progressively unlock the corresponding reward, creating a level-based reward journey.
</Info>

### Key characteristics

- **Multi-level progression** – Customers progress through multiple milestone levels within a single offer.
- **Progressive rewards** – Each level unlocks its own configured reward upon achievement.
- **Configurable outcome** – Rewards can be issued as Cashback, Reward Points, Voucher, Smart Tag, Partner Points, and other supported outcomes.
- **Cumulative progress tracking** – Eligible transactions accumulate toward each configured milestone level.
- **Subscription cycle support** – Progress is evaluated within the configured subscription cycle and can repeat based on the configured number of cycles.

The **Offer Type** is the foundation of the offer configuration journey. It determines how customers qualify for rewards.

For this guide, select **Gamified Offer**, which is designed to reward customers as they progressively achieve multiple milestone levels. This offer type is commonly used for tiered loyalty campaigns, engagement programs, spending challenges, and progressive reward journeys.

## Configure the Offer Scope

  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">

The **Offer Scope** defines where the Gamified Offer will be applicable. In this step, configure the basic offer details and specify the issuer and program(s) for which the offer should be available.

Configure the following:

- **Offer Name** – Enter a unique name for the offer.
- **Offer Description** – Provide a brief description of the offer.
- **Offer Duration** – Select the offer validity period.
- **Eligibility Level** – Choose whether the offer should be evaluated at the **Account Level** or **Customer Level**.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/0.4.1.png"
      alt="Step 4 - Configure Offer Applicability"
      className="w-[700px]"
    />
  </div>
</div>

Define the applicability of the offer by configuring:

- **Issuer** – Select the issuer.
- **Program Type** – Select the applicable product category.
- **Apply to all current and future programs** – Enable this option to apply the offer across all existing and future programs.
- **Program** – Select specific program(s) if the offer should not apply to all programs.
- **Enable Progress Transfer on Variant Upgrade** – Preserve a customer's progress across multiple gamification levels when they upgrade to another supported card or account variant.

<Info>
Without this enabled, a customer who upgrades mid-campaign starts their progress over on the new variant. Enable it for campaigns where you want customers to retain their progress across all configured gamification levels after a supported variant upgrade.
</Info>

### Example

Create a Gamified Offer by entering the offer details, selecting the required eligibility level, and choosing the applicable issuer and program(s). Enable **Apply to all current and future programs** if the offer should automatically apply to every program under the selected program type.

## Configure Offer User Base

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/0.5.png"
      alt="Step 5 - Select Static Base"
      className="w-[700px]"
    />
  </div>
</div>

Configure the **Offer User Base** to define which users are eligible for the Gamified Offer.

First, select the type of user base:

- **Static Base** – Uses a fixed list of eligible users that remains unchanged after the offer goes live.
- **Dynamic Config** – Continuously evaluates users against the configured eligibility criteria, allowing new users to become eligible over time.

Next, define the eligibility criteria for the selected user base.

Configure the following:

- **Eligibility** – Select the required user group or account scope.
- **Add Criteria** – Add one or more conditions to further refine the eligible user base.
- **Estimate User Base** – Calculate the estimated number of users that satisfy the configured criteria before publishing the offer.

### Example

Suppose the Gamified Offer should be available only to customers enrolled through a Smart Tag or a specific customer segment. Select the appropriate user base type, configure the eligibility criteria, add additional filters if required, and use **Estimate User Base** to verify the expected audience before proceeding.

<Tip>
Choose **Static Base** when the eligible audience is predefined and unlikely to change. Choose **Dynamic Config** when new customers should continue joining the eligible base as they satisfy the configured criteria. This is especially useful for long-running gamified campaigns where customers can become eligible throughout the offer duration.
</Tip>

## Configure Milestone Eligibility

    <img
      src="/images/Screenshot 2026-07-17 105521.png"
      alt="Step 6 - Configure Milestone Eligibility"
      className="w-[700px]"
    />
  </div>
</div>

Configure the milestone conditions that determine when a customer becomes eligible for the configured reward.

<Info>
**Offer User Base** determines *who* is evaluated for this offer. **Milestone Eligibility** and **Transaction Eligibility** — configured below — determine *which of their transactions* actually count toward the milestone. A customer can belong to the eligible user base and still never complete the milestone if their transactions don't satisfy these conditions.
</Info>

First, define how milestone progress should be tracked by selecting the appropriate aggregation method and configuring the milestone threshold.

Configure the following:

- **Aggregate By** – Select whether the milestone should be calculated based on the **Sum of Transaction Values** or the **Count of Transactions**.
- **Threshold** – Configure the comparison operator and the milestone value that customers must achieve.
- **Lock Milestone Progress on Achievement** – Enable this option to stop tracking progress after the milestone has been achieved.
- **Subscription Cycle Period** – Select the duration over which milestone progress should be tracked.
- **Number of Cycles** – Specify how many times the milestone can be repeated during the offer period.

<Warning>
Changing **Lock Milestone Progress on Achievement** or the **Subscription Cycle Period** after the offer is active may affect how in-progress customer milestones are evaluated. Review these settings carefully before publishing.
</Warning>

➡️ **Continue to:** **[Milestone Eligibility](/offer/milestone-eligibility)**

### Transaction Eligibility

    <img
      src="/images/Screenshot 2026-07-17 105533.png"
      alt="Step 6 - Configure Transaction Eligibility"
      className="w-[700px]"
    />
  </div>
</div>

Configure the transaction conditions that determine which transactions contribute towards milestone completion.

Select the required **Transaction Attribute**, choose the appropriate **comparison operator**, and provide the corresponding value. Add additional criteria if required and select the **Processing Date** used for milestone evaluation.

### Supported Transaction Attributes

- MCC
- MID
- TID
- POS Entry Mode
- Transaction Value
- Transaction Type
- Merchant Name
- Payer VPA
- Payee VPA

### Example

Suppose customers should receive a reward after completing **5 eligible transactions** of **₹500 or more** during a monthly subscription cycle. Configure the aggregation as **Count of Transactions**, set the threshold to **5**, and add transaction eligibility conditions to include only qualifying transactions.

<Tip>
Set **Number of Cycles** higher than 1 to turn a one-time milestone into a repeating reward — for example, rewarding customers every month they hit the spend threshold, rather than only once for the life of the offer.
</Tip>
## Configure Offer Calculation

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/a.3.png"
      alt="Step 7 - Configure Offer Calculation"
      className="w-[700px]"
    />
  </div>
</div>

Configure how rewards should be calculated for customers as they progress through multiple gamification levels.

First, select the **Rewarding Scheme** that determines how rewards are issued when customers unlock multiple levels.

Available options include:

- **Only The Biggest Reward** – Customers receive only the reward associated with the highest milestone level achieved.
- **Aggregated Reward** – Customers receive the rewards from all milestone levels they successfully complete.

Next, configure the reward calculation for each level.

Configure the following:

- **Threshold Value** – Specify the milestone value that customers must achieve to unlock the level.
- **Outcome Type** – Select the reward to be issued for the level.
- **Offer Calculation Rule** – Choose how the reward should be calculated.
- **Outcome Value** – Specify the reward amount or value for the selected level.
- **Add Level** – Add additional milestone levels and configure their corresponding rewards.

<Info>
Each milestone level can have its own threshold and reward configuration. Continue adding levels until the complete reward journey for the Gamified Offer has been configured.
</Info>

### Example

Suppose you want to reward customers with **₹100 cashback** after spending **₹5,000**, **₹250 cashback** after spending **₹10,000**, and **₹500 cashback** after spending **₹20,000**. Configure each milestone level with its corresponding threshold and reward. Then select **Only The Biggest Reward** if customers should receive only the highest unlocked reward, or **Aggregated Reward** if customers should receive rewards for every completed level.

➡️ **Continue to:** **[Offer Calculation](/offer/offer-calculation)**

Configure when and how the reward should be posted to eligible customers after they successfully complete the configured milestone.
