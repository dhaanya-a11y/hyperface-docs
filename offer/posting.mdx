## Overview

The **Posting** section defines **when** the configured offer benefit is credited to the customer's account and **under what conditions** the posting should occur.

After configuring **Usage Limits**, use this step to configure the posting schedule, define posting eligibility conditions, and specify the ledger narrations that should be recorded when benefits are posted or reversed.

<Note>

**Posting** controls only the reward crediting process. A customer must first satisfy all previously configured offer conditions before the configured posting rules are evaluated.

</Note>

---

## Enable Posting

Enable **Posting** to allow the configured offer benefit to be credited to the customer's account.

If Posting is disabled, the configured offer benefit is not posted even when all configured offer conditions are satisfied.

---

## Configure Posting Eligibility

Posting Eligibility defines the conditions that must be satisfied before the configured offer benefit is posted to the customer's account.

  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/v.13.png"
      alt="Posting Eligibility"
      className="w-[700px]"
    />
  </div>
</div>

To configure posting eligibility:

1. Select the required **Attribute**.
2. Configure the corresponding values.
3. Select the appropriate **Action**.
4. Click **Add More** to configure additional posting eligibility conditions, if required.

The following posting eligibility attributes are available:

| **Attribute** | **Description** |
|---------------|-----------------|
| **Account Status** | Identifies accounts based on their current account status. |
| **Account Smart Tag** | Identifies accounts based on the Smart Tags associated with the account. |
| **Account Block Code** | Identifies accounts based on the assigned account block code. |

---

### Account Status

Use **Account Status** to configure posting eligibility based on the customer's account status.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/v.15.png"
      alt="Account Status"
      className="w-[700px]"
    />
  </div>
</div>

Configure the following:

- Select the required account status.
- Select the appropriate **Action**:
  - **Allowed** – Posts the reward for customers matching the selected account status.
  - **Denied** – Does not post the reward for customers matching the selected account status.

---

### Account Smart Tag

Use **Account Smart Tag** to configure posting eligibility based on the Smart Tags associated with an account.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/v.16.png"
      alt="Account Smart Tag"
      className="w-[700px]"
    />
  </div>
</div>

Configure the Account Smart Tag as follows:

1. Select **List** or **Input**.
2. If **List** is selected, either:
   - Select **Create New List** to create a new Account Smart Tag list, or
   - Select an existing Account Smart Tag list from the available options.
3. If **Input** is selected, enter one or more Account Smart Tag values manually.
4. Select the required **Action**:
   - **Allowed** – Posts the reward for accounts associated with the selected or entered Account Smart Tag values.
   - **Denied** – Does not post the reward for accounts associated with the selected or entered Account Smart Tag values.

---

### Account Block Code

An **Account Block Code** is a code assigned to an account to identify a specific account status or restriction. Use this attribute to configure posting eligibility for accounts associated with the specified block code.

Configure the following:

- Enter one or more account block code values.
- Select the appropriate **Action**:
  - **Allowed** – Posts the reward for customers matching the specified account block code.
  - **Denied** – Does not post the reward for customers matching the specified account block code.

<Tip>

Configure multiple posting eligibility conditions when rewards should be posted only after all required conditions have been satisfied.

</Tip>

## Configure Offer Posting

Choose when the configured benefit should be credited.

| **Posting Option** | **Description** |
|--------------------|-----------------|
| **Post Immediately** | Credits the benefit immediately after the configured posting conditions are satisfied. |
| **Schedule** | Credits the benefit according to the configured schedule. |

### Post Immediately

Choose **Post Immediately** when the reward should be credited as soon as all configured posting conditions are satisfied.

**Example**

Credit cashback immediately after an eligible transaction has been processed.

---

### Schedule

Choose **Schedule** when the reward should be credited at a later time or on a configured schedule.

**Example**

Credit monthly rewards on the first day of the following month.

<Warning>

Changing the posting schedule after an offer becomes active may affect when future rewards are credited. Review the selected posting option before publishing the offer.

</Warning>

## Configure Narration

Provide the ledger narration recorded during reward posting and reward reversal.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/l.1.png"
      alt="Configure Narration"
      className="w-[700px]"
    />
  </div>
</div>

Configure the following fields:

| **Field** | **Description** | **Example** |
|-----------|-----------------|-------------|
| **Posting Narration** | Message recorded when the reward is posted. | Cashback credited for Fuel Offer |
| **Reversal Narration** | Message recorded when a posted reward is reversed. | Cashback reversed due to transaction reversal |

<Note>

Posting Narration and Reversal Narration are recorded for operational and audit purposes. Use clear and meaningful descriptions so posted and reversed rewards can be easily identified.

</Note>

---

## What Happens After Configuration?

Once the configured posting conditions are satisfied, the reward is credited according to the selected **Posting Option**.

If **Allow Reversal** was enabled during **Offer Calculation**, the configured **Reversal Narration** is used whenever a posted reward is subsequently reversed.

---

## Complete the Configuration

After completing the Posting configuration:

1. Verify that **Posting** is enabled, if required.
2. Review the configured **Posting Eligibility** conditions.
3. Confirm the selected **Posting Option**.
4. Review the configured **Posting Narration** and **Reversal Narration**.
5. Click **Continue** to proceed to the **Display Elements** configuration.
