## Overview

The **Offer Calculation** section defines how rewards are calculated for qualifying transactions. Once a transaction satisfies the configured eligibility criteria, the selected calculation rule is applied to determine the reward value.

Select the calculation rule that best aligns with the campaign requirements before proceeding with the remaining offer configuration.

## Offer Calculation Rules

Select an **Offer Calculation Rule** based on how the reward should be calculated for qualifying transactions.

|Offer Calculation Rule | Description | Example |
|------------------|-------------|---------|
| **Flat** | Awards a fixed reward amount for every qualifying transaction, regardless of the transaction value. | ₹100 Cashback |
| **Percentage** | Awards a percentage of the qualifying transaction amount. The reward varies based on the transaction value. | 5% Cashback |
| **Slab** | Awards different reward values based on predefined transaction value ranges or slabs. | ₹50 for ₹500–₹999, ₹100 for ₹1,000–₹1,999 |
| **Flat Multiplier** | Multiplies a fixed reward amount by a configured multiplier before awarding the final reward. | ₹100 × 2 = ₹200 Cashback |
| **Percentage with Min** | Calculates the reward as a percentage of the transaction amount while ensuring a minimum reward value is always provided. | 5% Cashback with a minimum of ₹50 |
| **Percentage with Max** | Calculates the reward as a percentage of the transaction amount but limits the reward to a configured maximum value. | 10% Cashback up to a maximum of ₹500 |
| **Percentage with Min and Max** | Calculates the reward as a percentage of the transaction amount while applying both minimum and maximum reward limits. | 5% Cashback with a minimum of ₹50 and a maximum of ₹500 |
| **Probabilistic Distribution** | Awards rewards based on predefined probability distributions, where each reward has a configured likelihood of being granted. | 10% chance of ₹500 Cashback, 90% chance of ₹50 Cashback |
| **Outcome Multiplier** | Multiplies the configured outcome value using a specified multiplier before issuing the final reward. | 100 Reward Points × 3 = 300 Reward Points |

### Flat

**When to use it**

Select **Flat** when every qualifying transaction should receive the same reward amount, regardless of the transaction value.

**Example**:

Reward customers with **₹100 cashback** for every qualifying transaction.

---
### Percentage

**When to use it**

Select **Percentage** when the reward should be calculated as a percentage of the qualifying transaction amount.

**Example**:

Reward customers with **5% cashback** on every qualifying purchase.

---
### Slab

**When to use it**

Choose **Slab** when different reward values should be issued based on predefined transaction value ranges.

**Example**:

- ₹50 cashback for transactions between **₹500–₹999**
- ₹100 cashback for transactions between **₹1,000–₹1,999**

### Flat Multiplier

**When to use it**

Choose **Flat Multiplier** when a fixed reward amount should be multiplied by a configured multiplier before being awarded.

**Example**:

The final reward is determined using the configured reward value and multiplier.

---
### Percentage with Min

**When to use it**

Choose **Percentage with Min** when the reward should be calculated as a percentage of the qualifying transaction amount while ensuring that a minimum reward value is always awarded.

**Example**:

The final reward is determined using the configured percentage and minimum reward value.

---
### Percentage with Max

**When to use it**

Choose **Percentage with Max** when the reward should be calculated as a percentage of the qualifying transaction amount while limiting the reward to a configured maximum value.

**Example**:

Refer to the configured percentage and maximum reward value for your offer.

---
### Percentage with Min and Max

**When to use it**

Choose **Percentage with Min and Max** when the reward should be calculated as a percentage of the qualifying transaction amount while applying both minimum and maximum reward limits.

**Example**:

Refer to the configured percentage, minimum reward value, and maximum reward value for your offer.

---
### Probabilistic Distribution

**When to use it**

The final reward is determined using the configured outcome value and multiplier.

**Example**:

Refer to the configured probability distribution for your offer.

---
### Outcome Multiplier

**When to use it**

Choose **Outcome Multiplier** when the configured outcome should be multiplied before being awarded.

**Example**:

Refer to the configured outcome value and multiplier for your offer.

<Tip>

Choose the calculation rule that best matches the intended reward strategy.

- Use **Flat** for fixed rewards.
- Use **Percentage** when rewards should scale with transaction value.
- Use **Slab** when different transaction ranges should receive different rewards.

</Tip>

After selecting an Offer Calculation Rule:

1. Configure the corresponding reward values.
2. Review the configured calculation before proceeding.

## Skip Cashback Capping (Optional)

Use **Skip Cashback Capping** to exclude cashback limits configured at specific capping levels during reward calculation.

The following cashback capping levels can be excluded during reward calculation:

| **Cashback Capping Level** | **Description** |
|----------------------------|-----------------|
| **Program Level** | Prevents the program-level cashback cap from being considered during reward calculation. |
| **Transaction Level** | Skips the cashback cap configured for individual transactions. |
| **Merchant Category Code (MCC)** | Ignores cashback restrictions associated with specific merchant categories. |
| **Merchant Identifier (MID)** |Excludes cashback limits configured for specific merchants. |
| **Currency Level** | Disregards cashback caps configured for transactions in specific currencies. |

<Warning>

Enable **Skip Cashback Capping** only when the campaign requires the configured offer to bypass one or more cashback capping rules.

</Warning>

## Allow Reversal

Enable **Allow Reversal** to reverse rewards when the corresponding qualifying transaction is subsequently reversed or refunded.

<Note>

When **Allow Reversal** is enabled, rewards issued for qualifying transactions are eligible for reversal if the original transaction is reversed or refunded.

</Note>

---
## What Happens After Configuration?

Once the **Offer Calculation** is configured, qualifying transactions are evaluated using the selected calculation rule. The calculated reward is then processed according to the remaining offer configuration, including **Budget**, **Usage Limits**, and **Posting**.

---
## Complete the Configuration

After configuring the **Offer Calculation**:

1. Review the selected **Offer Calculation Rule** and reward values.
2. Verify the **Skip Cashback Capping** and **Allow Reversal** settings, if applicable.
3. Click **Continue** to proceed to the **Budget** configuration.
