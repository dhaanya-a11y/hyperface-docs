## Overview

**Milestone Eligibility** defines how qualifying customer activity is accumulated, evaluated, and compared against a configured threshold to determine when a milestone is achieved.

During this step, configure the aggregation method, milestone threshold, subscription cycle, transaction eligibility conditions, and the date used to process the offer.

This configuration is available as part of the **Set-Up Offer** stage, after **Offer User Base** and before **Offer Calculation**.

<Note>

Milestone evaluation is based on three related configurations:

- **Offer User Base** defines **who** is evaluated.
- **Transaction Eligibility** defines **which transactions** contribute towards milestone progress.
- **Milestone Eligibility** defines **how qualifying activity is accumulated** and **when the milestone is achieved**.

</Note>

## Aggregate By

**Aggregate By** determines how qualifying customer activity is accumulated while evaluating milestone progress.

| **Consideration** | **Sum of Transaction Values** | **Count of Transactions** |
|-------------------|-------------------------------|---------------------------|
| **Progress is based on** | Total value of qualifying transactions | Number of qualifying transactions |
| **Recommended Use** | Campaigns based on cumulative spend | Campaigns based on transaction frequency |

### Sum of Transaction Values

Select **Sum of Transaction Values** when milestone progress should be calculated using the cumulative value of qualifying transactions.

A milestone is achieved once the accumulated transaction value satisfies the configured threshold.

**Example**

If the threshold is **₹10,000**, qualifying transactions of **₹2,000**, **₹3,000**, and **₹5,000** together complete the milestone.

---

### Count of Transactions

Select **Count of Transactions** when milestone progress should be calculated using the number of qualifying transactions instead of their value.

A milestone is achieved once the configured transaction count is reached.

**Example**

If the threshold is **10**, the milestone is achieved after **10 qualifying transactions**, regardless of their value.

---

## Define Threshold

**Define Threshold** specifies the target against which accumulated milestone progress is evaluated.

The configured threshold works together with the selected **Aggregate By** method to determine when a milestone is achieved.

For example:

> Reward the customer when eligible spends are **Greater Than** `10000`.

---

## Lock Milestone Progress on Achievement

Enable **Lock Milestone Progress on Achievement** to stop milestone progress from changing after the configured threshold has been reached.

Once enabled, additional qualifying transactions or transaction reversals do not modify the recorded milestone progress.

<Tip>

Disable this option if milestone progress should continue accumulating after the threshold has been achieved—for example, when configuring multiple milestone levels.

</Tip>

---

## Subscription Cycle Period

**Subscription Cycle Period** specifies how frequently milestone progress is evaluated and reset.

For example, selecting **Quarter** evaluates milestone progress during each calendar quarter and resets the accumulated progress at the beginning of the next quarter.

Select the cycle that matches the period in which the milestone should be measured.

| **Option** | **Description** |
|---|---|
| **5-Minutes** | Tracks qualifying activity within a 5-minute period. |
| **Day** | Tracks qualifying activity on a daily basis. |
| **Week** | Tracks qualifying activity on a weekly basis. |
| **Quarter** | Tracks qualifying activity over a three-month period. |
| **Calendar Month** | Follows the standard calendar month, from the 1st day through the last day of the month. |
| **Billing Month** | Follows the customer's billing cycle, which may start and end on dates different from the calendar month. |
| **Calendar Year** | Follows the standard calendar year, from January 1 through December 31. |
| **Anniversary Year** | Defines a 12-month period based on the customer's anniversary date rather than the calendar year. |
| **Custom** | Allows a custom cycle period to be configured. |
| **Account Creation Date** | Uses the customer's account creation date as the starting reference for the cycle. |

---

## Number of Cycles

**Number of Cycles** specifies the number of subscription cycles during which milestone evaluation remains active.

For example, a value of **2** keeps the milestone active for **2 subscription cycles**.

<Note>

These two settings work together:

- **Subscription Cycle Period** determines how frequently milestone progress resets.
- **Number of Cycles** determines how long milestone evaluation remains active.

</Note>

---

## Example

### Quarterly Spend Milestone

To reward customers who spend more than **₹10,000** in eligible transactions every quarter for **2 subscription cycles**:

1. Select **Aggregate By** as **Sum of Transaction Values**.
2. Configure **Define Threshold** as **Greater Than** `10000`.
3. Select **Quarter** under **Subscription Cycle Period**.
4. Set **Number of Cycles** to **2**.

Customers who satisfy the configured spend threshold during a quarter achieve the milestone for that cycle.

## Transaction Eligibility

**Transaction Eligibility** defines which qualifying transactions contribute towards milestone progress.

Only transactions that satisfy the configured eligibility conditions are considered while calculating milestone progress.

<Warning>

Only transactions that satisfy the configured transaction eligibility conditions contribute towards milestone progress.

Transactions that do not satisfy these conditions are excluded from milestone evaluation.

</Warning>

Configure one or more of the following transaction attributes:

| **Transaction Attribute** | **Description** | **Example** |
|---------------------------|-----------------|-------------|
| **MCC** | Merchant Category Code associated with the transaction. | Fuel Stations |
| **MID** | Merchant Identifier associated with the transaction. | Merchant MID |
| **TID** | Terminal Identifier used for the transaction. | POS Terminal |
| **POS Entry Mode** | Method used to capture payment information. | Contactless |
| **Transaction Value** | Transaction amount used during eligibility evaluation. | Greater than ₹1,000 |
| **Transaction Type** | Type of transaction being processed. | Purchase |
| **Sovereignty Indicator** | Indicates whether the transaction is domestic or international. | Domestic |
| **Transaction Code** | Transaction code associated with the transaction. | Purchase Transaction |
| **Payer VPA** | Payer Virtual Payment Address for UPI transactions. | customer@upi |
| **Payee VPA** | Payee Virtual Payment Address for UPI transactions. | merchant@upi |

<Tip>

Not every transaction attribute is applicable to every payment channel.

- **Payer VPA** and **Payee VPA** are applicable only to UPI transactions.
- **MCC**, **MID**, and **TID** are applicable only to card transactions.

Configure only the attributes relevant to the payment channel supported by the offer.

</Tip>

Multiple transaction eligibility conditions can be configured using **Add More**.

<Note>

This section uses the same transaction eligibility attributes available during Transactional Offer configuration.

</Note>

## Date for Offer Processing

Select the date that should be used while processing the offer.

If no option is selected, processing follows the issuer-level default configuration.

|------------|-----------------|
| **Transaction Date** | Processes the offer based on the transaction date. |
| **Posting Date** | Processes the offer based on the posting date. |

<Note>

If no option is explicitly selected, offer processing follows the issuer-level default configuration.

</Note>

## What Happens After Configuration?

Once the configuration is complete:

- Eligible customer activity is accumulated using the selected **Aggregate By** method.
- Only transactions that satisfy the configured **Transaction Eligibility** conditions contribute towards milestone progress.
- Progress is evaluated against the configured **Threshold** during each subscription cycle.
- When the configured threshold is achieved, the milestone is completed and the reward proceeds to **Offer Calculation**.
