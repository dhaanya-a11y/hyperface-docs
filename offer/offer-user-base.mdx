## Overview

The **Offer User Base** defines the group of customers who are eligible to participate in an offer. It allows issuers to identify the intended customer segment and determine how eligible customers are enrolled into the campaign.

Once the user base is configured, the subsequent eligibility rules evaluate whether the customer's transactions or activities qualify for the configured reward.

<Note>

**Offer User Base** determines **who** is evaluated for an offer. The subsequent eligibility configuration—such as **Transaction Eligibility**, **Milestone Eligibility**, or **Gamification Levels**—determines **whether the customer's activity qualifies** for a reward.

</Note>

<Warning>

Being part of the **Offer User Base** does **not** guarantee a reward. Customers must also satisfy the configured eligibility criteria before a reward is issued.

</Warning>

<Note>

Eligibility is evaluated within the **Offer Scope** configured earlier. The selected **Eligibility Level** (**Account Level** or **Customer Level**) determines whether the criteria are evaluated for an individual account or across all of a customer's accounts.

</Note>

## Static Base vs Dynamic Config

| Consideration | Static Base | Dynamic Config |
|---|---|---|
| Audience | Fixed once the offer is published | Automatically determined by evaluating customers against the configured criteria during the evaluation period |
| Best for | A known, closed audience decided in advance | Criteria-based eligibility that should reflect current customer data rather than a fixed list |
| Evaluation | Once, before publishing | Ongoing, against live customer data |

### Static Base

Select **Static Base** when the set of eligible users is fixed before the offer is published. Once the offer is activated, the user base remains unchanged unless the offer is modified.

**Example**

A bank wants to run an invite-only campaign for **2,000** pre-selected, relationship-manager-nominated customers. Since the list is decided in advance and shouldn't change once the campaign starts, **Static Base** is the right choice.

### Dynamic Config

Select **Dynamic Config** when the eligible user base should be automatically determined rather than fixed in advance. Customers who satisfy the configured conditions during the evaluation period are included in the eligible user base.

**Example**

A bank wants a welcome cashback offer to apply to every savings account opened during the offer period. New accounts keep opening continuously, so a fixed list decided on day one would miss later joiners—**Dynamic Config** with an **Account Creation Date** criterion keeps the eligible set current.

<Tip>

Choose **Static Base** when the eligible audience is predefined and unlikely to change.

Choose **Dynamic Config** when eligibility should automatically adapt as customer information changes over time.

</Tip>

## Configure Eligibility

Whichever user base type you select, configure the eligibility criteria used to identify eligible customers.

| Eligibility Option | Description | Example |
|--------------------|-------------|---------|
| **Smart Tag** | Identifies users based on a predefined Smart Tag assigned to customers. | Premium Customer |
| **Accounts** | Defines eligible users using account-related information. | Savings Account |
| **Switch Account Number** | Identifies users using their Switch Account Number. | 1234567890 |
| **Birthdate** | Targets customers based on their date of birth. | Customers born in July |
| **Account Creation Date** | Targets customers based on when their account was created. | Accounts created after 01 Jan 2025 |

### Smart Tag

Use the **Smart Tag** eligibility type to identify customers based on an existing Smart Tag.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/v.1.png"
      alt="Smart Tag Eligibility"
      className="w-[700px]"
    />
  </div>
</div>

Configure the Smart Tag as follows:

1. Select **List** or **Input** to specify the Smart Tag values.
2. If **List** is selected, either:
   - Select **Create New List** to create a new Smart Tag list, or
   - Select an existing Smart Tag list from the available options.
3. If **Input** is selected, enter one or more Smart Tag values manually.
4. Select **Allowed** to include customers associated with the specified Smart Tag values, or **Denied** to exclude them.

### Birthdate

Use the **Birthdate** eligibility type to identify customers based on their birthdate.

Configure the Birthdate eligibility as follows:

1. Select one of the available birthdate options:
   - **On the Birthday** – Evaluates customer eligibility on the customer's birthday.
   - **In the Birth Day Week** – Evaluates customer eligibility during the customer's birthday week.
   - **In the Birth Day Month** – Evaluates customer eligibility during the customer's birthday month.
   - **Custom** – Allows you to configure a custom birthdate-based eligibility condition.

### Account Creation Date

Use the **Account Creation Date** eligibility type to identify customers based on their account creation date.

Configure the Account Creation Date eligibility as follows:

1. Select one of the available account creation date options:
   - **On Account Creation Day** – Evaluates customer eligibility on the day the account is created.
   - **On Anniversary Date** – Evaluates customer eligibility on each anniversary of the account creation date.
   - **X Days After for Y Days** – Evaluates customer eligibility starting **X** days after the account creation date for **Y** days.
   - **X Days From Account Creation Day** – Evaluates customer eligibility after **X** days from the account creation date.

## Estimate User Base

<Warning>
Review the estimated user count before proceeding. If the estimate is significantly higher or lower than expected, verify the configured eligibility criteria to ensure the intended audience has been selected.
</Warning>

Once the eligibility criteria have been configured:

1. Click **Estimate User Base** to calculate the estimated number of eligible users.
2. Review the estimated user count displayed by the system.
3. Verify that the estimated audience aligns with the campaign requirements.
4. Click **Continue** to proceed to the next configuration step.
