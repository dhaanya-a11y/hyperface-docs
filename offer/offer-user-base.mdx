## Overview

The **Offer User Base** defines the customer segment that is considered for an offer. During this step, configure how eligible customers are identified and enrolled into the campaign.

Once the Offer User Base is configured, the subsequent eligibility configuration evaluates whether the customer's transactions or activities satisfy the conditions required to receive the configured offer benefit.

<Note>

**Offer User Base** determines **who** is considered for an offer. The subsequent eligibility configuration—such as **Transaction Eligibility**, **Milestone Eligibility**, or **Gamification Levels**—determines **whether the customer's activity qualifies** for the configured offer.

</Note>

<Warning>

Being included in the **Offer User Base** does not guarantee that a customer receives an offer benefit. Customers must also satisfy the configured eligibility conditions before rewards are issued.

</Warning>

<Note>

Eligibility is evaluated within the **Offer Scope** configured earlier. The selected **Eligibility Level** (**Account Level** or **Customer Level**) determines whether the criteria are evaluated for an individual account or across all of a customer's accounts.

</Note>

## User Base Types

| Consideration | Static Base | Dynamic Config |
|---|---|---|
| Customer Segment | Fixed once the offer is published | Automatically determined by evaluating customers against the configured criteria during the evaluation period |
| Recommended Use | A known, closed audience decided in advance | Criteria-based eligibility that should reflect current customer data rather than a fixed list |
| Evaluation | Once, before publishing | Ongoing, against live customer data |

### Static Base

A **Static Base** is used when the eligible customer segment is known before the offer is published. Once configured, the selected customer segment remains unchanged unless the offer configuration is updated.

**Example**

A bank wants to run an invite-only campaign for **2,000** pre-selected, relationship-manager-nominated customers. Since the list is decided in advance and shouldn't change once the campaign starts, **Static Base** is the right choice.


### Smart Tag

Use **Smart Tag** to identify customers associated with one or more Smart Tags.

Configure the Smart Tag as follows:

1. Select **List** or **Input** to specify the Smart Tag values.
2. If **List** is selected, either:
   - Select **Create New List** to create a new Smart Tag list, or
   - Select an existing Smart Tag list from the available options.
3. If **Input** is selected, enter one or more Smart Tag values manually.
4. Select **Allowed** to include customers associated with the specified Smart Tag values, or **Denied** to exclude them.

### Birthdate

Configure the Birthdate eligibility as follows:

1. Select one of the available birthdate options:
   - **On the Birthday** – Evaluates customer eligibility on the customer's birthday.
   - **In the Birth Day Week** – Evaluates customer eligibility during the customer's birthday week.
   - **In the Birth Day Month** – Evaluates customer eligibility during the customer's birthday month.
   - **Custom** – Allows you to configure a custom birthdate-based eligibility condition.

   - **On Account Creation Day** – Evaluates customer eligibility on the day the account is created.
   - **On Anniversary Date** – Evaluates customer eligibility on each anniversary of the account creation date.
   - **X Days After for Y Days** – Evaluates customer eligibility starting **X** days after the account creation date for **Y** days.
   - **X Days From Account Creation Day** – Evaluates customer eligibility after **X** days from the account creation date.

### Dynamic Config

A **Dynamic Config** automatically determines the eligible customer segment by evaluating customers against the configured criteria throughout the offer period.

**Example**

A bank wants a welcome cashback offer to apply to every savings account opened during the offer period. New accounts keep opening continuously, so a fixed list decided on day one would miss later joiners—**Dynamic Config** with an **Account Creation Date** criterion keeps the eligible set current.

<Tip>

- Choose **Static Base** when the customer segment is predefined before the offer is published.
- Choose **Dynamic Config** when the eligible customer segment should be determined automatically using configured criteria.

</Tip>

### Opt-In

Use **Opt-In** to configure customer participation based on the selected eligibility criteria.

    <img
      src="/images/g.1.png"
      alt="Configure Offer User Base"
      className="w-[700px]"
    />
  </div>
</div>

Configure the Opt-In eligibility as follows:

1. Select **Opt-In** as the eligibility type.
2. Select one of the available eligibility criteria:
   - **Accounts in Scope**
   - **Smart Tag**
3. Configure the selected eligibility criteria.
4. Click **Estimate User Base** to calculate the estimated number of eligible customers.
5. Click **Continue** to proceed to the next configuration step.
Eligible customers are identified based on the selected criteria, such as **Accounts in Scope** or **Smart Tag**.

### Smart Tag Attachment

Use **Smart Tag Attachment** to configure customer eligibility based on the attachment of a selected Smart Tag.

<div className="my-8 flex justify-center">
  <div className="overflow-hidden rounded-2xl border border-gray-200 bg-white shadow-lg">
    <img
      src="/images/v.8.png"
      alt="Smart Tag Attachment"
      className="w-[700px]"
    />
  </div>
</div>

Configure the Smart Tag Attachment as follows:

1. Select **Smart Tag Attachment** as the eligibility type.
2. Click **Select Smart Tag** and choose the required Smart Tag.
3. Configure the following fields:
   - **Offer Activation Date** – Specify the number of days after Smart Tag attachment to activate the offer for the customer.
   - **Subscription Duration** – Specify the subscription duration for the dynamic customer segment.
   - **Subscription Cut-Off Date** – Specify the subscription cut-off date for the dynamic customer segment.
4. Click **Estimate User Base** to calculate the estimated number of eligible customers.
5. Click **Continue** to proceed to the next configuration step.
## Estimate User Base

<Warning>
Review the estimated user count before proceeding. If the estimate is significantly higher or lower than expected, verify the configured eligibility criteria to ensure the intended audience has been selected.
</Warning>

Once the eligibility criteria have been configured:

1. Click **Estimate User Base**.
2. Review the estimated customer count.
3. Verify that the estimated audience matches the intended campaign.
4. Click **Continue** to proceed to the next configuration step.
